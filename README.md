# Hunter 2 — FAST v0020-fast

Отдельная агрессивная копия Gift Hunter для второго Telegram-аккаунта. Она не должна заменять или обновлять работающий v0018.

## Что изменено

FAST реагирует на точное появление `цель − 1` и сразу запускает заранее подготовленный платёжный запрос:

```text
точно найден #3332
→ RAM-флаг «залп сделан»
→ запуск заранее созданного SendStarsFormRequest
```

До запуска платежа нет:

- дополнительной сетевой проверки целевого slug;
- записи `payment_hold` на диск;
- логирования и обновления карточки;
- повторного чтения настроек;
- обновления платёжной формы;
- автоматической повторной оплаты.

После отправки бот проверяет результат, сохраняет подтверждённые номера и ставит неизвестные результаты на сверку. Это уже не влияет на место финансового запроса в гонке.

## FAST-залп 1–5

В нижней клавиатуре есть тумблер `💥 Залп: 1`. Каждое нажатие переключает:

```text
1 → 2 → 3 → 4 → 5 → 1
```

По умолчанию установлен **один выстрел**. При залпе `N` нужно выбрать минимум `N` одинаковых неулучшенных подарков. Для каждого экземпляра заранее создаётся отдельная платёжная форма и отдельный MTProto-запрос. В момент триггера запросы запускаются конкурентно через одно горячее Telethon-соединение.

Залп больше одного может списать полную стоимость всех операций и выдать целевой номер только одному подарку, а остальным — следующие номера. Изменение размера залпа автоматически выключает LIVE: оплату нужно включить заново, чтобы увидеть и подтвердить новый максимальный расход.

## Тихая зона

Когда до цели остаётся не больше `FAST_QUIET_DISTANCE` номеров, по умолчанию 5:

- отключается монитор редактирования карточки;
- пропускается периодический агрегатный запрос счётчика;
- отключается сборщик мусора Python до окончания охоты;
- сканер продолжает только точные проверки последовательных slug;
- платёжные формы при необходимости всё ещё освежаются заранее, пока целевой предшественник не появился.

После остановки или результата GC включается обратно.

## Критическое отличие от v0018

FAST **намеренно не проверяет существование самой цели после обнаружения `цель − 1`**. Это экономит один полный сетевой круг, но повышает финансовый риск: если другой запрос уже занял цель, FAST всё равно улучшит подарок и может получить следующий номер.

Для текущего запуска с одним выстрелом разумно держать на втором аккаунте только сумму одного улучшения. Для залпа 2–5 баланс должен покрывать все выбранные операции.

## Отдельный деплой в Coolify

Не обновляй существующий сервис v0018. Создай новый репозиторий и новый Coolify-сервис.

Обязательная изоляция:

```env
BOT_TOKEN=<токен нового бота>
DATA_DIR=/app/data
MT_SESSION=/app/data/hunter2_fast_account
MAX_UPGRADE_STARS=3000
FAST_QUIET_DISTANCE=5
```

Также нужны:

- другой Telegram-аккаунт;
- другой канал с неулучшенным подарком;
- новый Bot API token;
- новый persistent volume;
- одна реплика сервиса;
- отдельный `*.session` файл.

В приложенном `docker-compose.yaml` volume называется `hunter_2_fast_data`, поэтому он не совпадает со старым `pod_gift_data`.

## Авторизация второго аккаунта

После первого деплоя открой Termius и выполни внутри нового контейнера:

```bash
python /app/main.py auth
```

Вводи номер, код и 2FA-пароль именно второго Telegram-аккаунта. Первая авторизация не затрагивается, потому что новый сервис использует отдельный volume и `MT_SESSION`.

## Порядок настройки

1. Открой нового бота и заверши привязку.
2. Выбери канал второго аккаунта.
3. Выбери один подарок для `Залп: 1`.
4. Задай цель `3333`.
5. Убедись, что `MAX_UPGRADE_STARS` выше цены одного улучшения.
6. Нажми `🛡 Оплата: ВЫКЛ`, чтобы включить LIVE и заранее подготовить запрос.
7. Запусти сканер.
8. Не нажимай кнопки и не перезапускай сервис в критическом окне.

Команда `/version` должна вернуть:

```text
Hunter 2 — FAST v0020-fast
```

## Границы гарантии

Код не может зарезервировать номер и не управляет порядком обработки на стороне Telegram. Залп 1–5 и сокращённый hot path только уменьшают локальную задержку и увеличивают количество независимых попыток. Реальная гонка зависит от маршрута до Telegram, нагрузки его дата-центра и чужих уже отправленных запросов.
